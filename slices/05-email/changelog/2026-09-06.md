# Preflight, and the Resend account steps

## What changed

A `## Preflight` block, and a `USER-SETUP.md` holding what only a person can do.

The probe here is the weakest kind and honest about it: `grep -l RESEND_API_KEY
apps/graphql/.env*` finds a key already on this machine but can say nothing about whether an
account exists. No command can. So the account is one of the few things that genuinely reaches
the user as a question — and it blocks **Round 2 only**, which the preflight block states,
because local rendering sends nothing and the whole package is provable without a key.

## Moved out of the REFERENCE

`### 1. Resend account and API key — one time` is now a pointer. The signup, the **Sending
access** scope, and the shared-sender limit live in `USER-SETUP.md`.

That limit is the reason this section is worth keeping intact rather than compressing to a
signup link: `onboarding@resend.dev` delivers **only to the address the account was created
with**, and every other recipient is rejected at Resend rather than by this code. A user who
does not read that sentence reads a rejection whose cause is nowhere in the repo. It decides
what goes in `MAIL_TEST_RECIPIENTS`, which is the value the production gate refuses a send
without.

The `wrangler secret put` step stays available to the user as an interactive command but is no
longer described as theirs alone — a Resend key is not a live payment credential, and SKILL.md
§6 already governs when the agent may move a secret down a pipe without printing it.
