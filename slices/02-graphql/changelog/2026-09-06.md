## REFERENCE corrections

Two defects, both of which would have hit any project building this slice.

**`apps/web`'s `cf-typegen` was written as `wrangler types …` alone, silently dropping
`next typegen`.** The web-shell slice folds `next typegen` into that package's `codegen`
script precisely so a fresh clone can generate the route types Next writes into the gitignored
`.next/types/`; `pnpm pkg set` replaces rather than appends, so this slice's line deleted the
fix the previous slice had installed. A developer machine cannot see this — the directory is
already there — and only the fresh-clone row catches it, as `TS2304: Cannot find name
'LayoutProps'`. Corrected the command and generalised the lesson: this slice restructures two
scripts an earlier slice owns, and neither may be written from the document without first
reading what is in the repo. That is the same rule the slice already states for
`wrangler.jsonc` and `.env.example`, now stated for scripts as well, which is where it was
missing.

**No `CLAUDE.md` hunk existed at all**, though the slice adds a whole app and installs a
skill. This is not cosmetic: a project that updates the package map drifts against its own
plan and fails `pnpm docs:check`, while one that does not ships a map missing half the
workspace — so the slice was unbuildable-as-written either way once someone noticed the app
was undocumented. Added a `## The package map` section carrying a `diff` hunk, since slice 0
owns the file's base heredoc and `docs:check` composes hunks in slice order.

## Round 2 (production)

Nothing needed correcting — both deploys went green first try, API then web, and the page
showed `production` for both env values. Recording what was *confirmed* rather than changed,
since these were claims the REFERENCE made that only a real deploy can settle:

- `await connection()` does its job. `next build` runs as part of `deploy:production` and
  prerenders `/` by default; the build completed, so the request-time opt-out held. This is
  the failure the REFERENCE says nothing local catches, and it stayed caught.
- The service binding resolves at upload time. The web deploy's binding table listed
  `env.API` against the API Worker's name, having been uploaded second.
- The deployed CORS allowlist behaves as `cors.test.ts` asserts against a local
  `worker.fetch` — verified over the wire with `curl`. The **one-entry short-circuit is real
  in production**: a disallowed origin receives a header naming the *allowed* origin rather
  than a missing header or its own. Worth having pinned in a test, because it reads like a
  leak and is not one, and because production runs exactly that one-entry shape. No
  `access-control-allow-credentials` on any response, and a request with no `Origin` gets no
  CORS headers at all.
